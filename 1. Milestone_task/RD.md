# Проект №1 "Project_PEO_001»: Оптимизация крупных массивов данных
## Суть проблемы и архитектурный контекст
Существует единый, спроектированный ранее, excel – файл: ГПР (график производства работ). Это не просто таблица, а целая система, которая включает в себя ввод данных, хранилище данных, автоматизированные расчеты объемов работ и их трудозатрат – как планируемых, так и фактических, систему планирования работ, поставки материала, а также аналитические витрины, где все данные так или иначе связаны между собой. 
Один из листов содержит список работ – это самый ключевой лист, от которого исходит вся дальнейшая паутина процессов (рисунок 1). На этом же листе, у каждой работы, существуют плановые объемы, единицы измерения, нормы по трудозатратам, расчет самих трудозатрат – для более чем (200) двухсот шифров (общая сумму строк доходит до 6000 тысяч, где на один только шифр может быть от 10 до 100 строк с работами).

 <img width="974" height="421" alt="image" src="https://github.com/user-attachments/assets/8dfcf4a9-2f03-47e9-bbb7-0231d749b02b" />

Каждая строка с работой, разбивается на соответствующие столбцы, и имеет уникальный составной ключ – «Ключ к декаде» (графа № 4 на рисунке 1), который включает себя: вид работ (группа), шифр – «короткий ключ принадлежности к шифру», а также текстовые значения единиц измерения.
Такая комбинация позволяет проводить группировку по составному ключу и гарантированно получать результат агрегации по соответствующим видам работ и их единицам измерения. 
Единицы измерения важны в данном ключе, так как виды работ (группы) могут содержать в себе работы с разными единицами измерения (мы не можем суммировать и квадратные и кубические метры – к примеру).
Список работ (то есть содержание данного листа) формируется из массива сметных выгрузок, однако те содержат в себе масштабный разнобой укрупненных нормативов и единиц измерения: площадей (`м2`, `10 м2`, `100 м2`, `1000 м2`), кубатуры (`м3`, `10 м3`, `100 м3`, `1000 м3`), штучных спецификаций (`шт`, `10 шт`, `100 шт`, `1000 шт`), а также линейных объектов (`м`, `10 м`, `100 м`).

Этот хаос, усугубленный дефектами ручного ввода (знаки пунктуации вида `шт.`, `м.`, случайные пробелы и склейки), делал невозможным корректный расчет сквозной аналитики строительного производства. Как указывалось выше, текстовые значения единиц измерения напрямую входят в состав уникального укрупненного аналитического ключа («Ключ к декаде»), по которому происходит необходимая группировка. Из-за синтаксического разнобоя однородные технологические процессы дробились, а алгоритмы группировки не могли корректно схлопывать и суммировать физические объемы. Это приводило к критическому раздуванию расчетов, дублированию веток и плодило системные аномалии в бюджете человеко-часов.
**Цель проекта:** Ликвидировать разнобой, привести данные к единым чистым эталонам (`м2`, `м3`, `шт`, `м`), пропорционально пересчитав исходные физические объемы (из 1000 м3 в м3, как пример), планы и элементные нормы расхода времени ГЭСН (ч/ч) для обеспечения абсолютной структуры составных аналитических ключей.

## Системный тупик ИИ (Интерфейсный барьер)
Была предпринята попытка обработать массив «в лоб» через контекстное окно ИИ-ассистента, в ходе которой столкнулся с некоторыми барьерами:
* Выгружая массивы данных для их обработки в чат, были выявлены системные ограничения и проблемы: ограничения по выводу данных, ИИ-галлюцинации (ложные данные). Все это влекло за собой повышенный контроль ИИ-ассистента и высокие трудозатраты, что было неприемлемо.
* При попытке обойти контекстное окно чата (предоставив данные в чат через сторонний сайт), были обнаружены иные ограничения - внутренние фильтры безопасности или лимиты генерации платформы блокировали, обнуляли или скрывали (схлопывали через `...`) длинные табличные выводы.


## Нестандартное решение (Связка «Оператор + ИИ»)
Вместо бесперспективной борьбы с текстовыми фильтрами, перестроил архитектуру взаимодействия и вынес вычисления за пределы чата:
1. **Инфраструктура (Оператор):** Развертывание сырого массива данных на внешнем репозитории GitHub (`task1.txt`) для сквозного доступа – передача прямой ссылки в чат ИИ, предварительно сделав репозиторий открытым (рисунок 3)

3. **Инструмент автоматизации (ИИ):** Вместо прямого запроса на выдачу обработанного массива данных – запрос на разработку точечного макроса VBA под внутренний движок Excel для мгновенного локального пересчета, на основе переданных данных.
4. **Локальное выполнение (Оператор):** Выполнение принятого макроса напрямую в рабочую книгу Excel и его отладка (при наличии ошибок). При получении удовлетворяющего макроса, его активация и приведение базы к эталону за считанные секунды в обход ограничений сети.
## Инициализация сессии новой сессии на основе 
* В ходе обработки, алгоритм макроса модернизированы для динамического подавления знаков пунктуации (точечных аномалий вида `шт.` и `м.` - с точками) и случайных пробелов, что позволило схлопнуть грязный ввод в единый строгий эталон. 

## Закрывающий инструмент (VBA Макрос) под task1_971row
- код сгенерирован ИИ, протестирован оператором
```vba
' Данный макрос локально выравнивает единицы измерения к м2, 
' корректируя объемы (× коэффициент) и нормы расхода (/ коэффициент).
Sub ConvertUnitsToM2_StrictSafe()
    Dim ws As Worksheet
    Dim lastRow As Long
    Dim i As Long
    Dim unitStr As String
    Dim coef As Double
    
    ' Работаем строго с текущим активным листом Excel
    Set ws = ActiveSheet
    
    ' Находим последнюю заполненную строку по Столбцу 1 (А)
    lastRow = ws.Cells(ws.Rows.Count, "A").End(xlUp).Row
    
    ' Выключаем обновление экрана для моментального расчета
    Application.ScreenUpdating = False
    
    ' Начинаем со 2-й строки, так как 1-я — это шапка таблицы
    For i = 2 To lastRow
        ' Важнейший сброс: для каждой новой строки коэффициент равен 1
        coef = 1
        
        ' Берем текст из Столбца 6 (Ед.изм.), убираем пробелы и переводим в строчные буквы
        unitStr = Trim(ws.Cells(i, 6).Value)
        unitStr = Replace(unitStr, " ", "")
        unitStr = LCase(unitStr)
        
        ' Жесткая проверка на абсолютное совпадение текстовых строк
        If unitStr = "10м2" Then
            coef = 10
        ElseIf unitStr = "100м2" Or unitStr = "100м" Then
            coef = 100
        ElseIf unitStr = "1000м2" Then
            coef = 1000
        End If
        
        ' Точечный пересчет запускается ТОЛЬКО если найден укрупненный коэффициент
        If coef > 1 Then
            ' Столбец 3: Объем (Исходный) -> Умножаем на коэффициент
            If IsNumeric(ws.Cells(i, 3).Value) And ws.Cells(i, 3).Value <> "" Then
                ws.Cells(i, 3).Value = ws.Cells(i, 3).Value * coef
            End If
            
            ' Столбец 4: Вып. до 04.2026 -> Умножаем на коэффициент
            If IsNumeric(ws.Cells(i, 4).Value) And ws.Cells(i, 4).Value <> "" Then
                ws.Cells(i, 4).Value = ws.Cells(i, 4).Value * coef
            End If
            
            ' Столбец 5: План на объем Begin -> Умножаем на коэффициент
            If IsNumeric(ws.Cells(i, 5).Value) And ws.Cells(i, 5).Value <> "" Then
                ws.Cells(i, 5).Value = ws.Cells(i, 5).Value * coef
            End If
            
            ' Столбец 6: Переименовываем укрупненную единицу в чистые м2
            ws.Cells(i, 6).Value = "м2"
            
            ' Столбец 7: Норма расхода ч/ч -> Жестко делим на коэффициент
            If IsNumeric(ws.Cells(i, 7).Value) And ws.Cells(i, 7).Value <> "" Then
                ws.Cells(i, 7).Value = ws.Cells(i, 7).Value / coef
            End If
        End If
    Next i
    
    ' Возвращаем обновление экрана в исходное состояние
    Application.ScreenUpdating = True
    
    MsgBox "Контроль завершен! Укрупненные единицы приведены к м2. Строки с обычными м2 полностью защищены от изменений.", vbInformation, "Успех"
End Sub


```
